## 二、组装最后三个文件

### 2.1 `harness.py` —— 所有内容汇聚的地方
- 需要定义/实例化一个 **Harness 类**；每个 harness 是该类的一个实例。
- 创建 harness 时需定义：
  - **循环结构**（loop）；
  - **策略**（yolo / 安全模式）作为参数；
  - **工具**（默认配置）；
  - **子智能体工具**（若启用）；
  - 构建系统提示的方法。
- 这是整个系统的"心脏运行循环"汇聚处。回顾各模块对应天数：循环（D1）、工具（D2）、odcs.md 记忆（D3）、技能（D3）、子智能体（D4）。
- **预算检查时机差异（设计选择）**：
  - **Py**：模型调用后、工具运行后再检查上下文预算。
  - **Hermes / Codex**：在**调用模型前**检查预算。
  - Odysseus 采用 Py 模型（模型调用后、工具运行后）。
- **模块化优势**：可随时加短期记忆（memory.py）、可观测性（OpenTelemetry 追踪）、评估器（evaluator.py）等。

### 2.2 `fleet.py` —— 舰队（多个实例）
- 创建 Harness 类的**多个实例**，每个有独立 name / workdir / task，各在独立工作目录运行。
- 例：让 harness 并行完成 25 个独立项目（非子智能体，而是完全独立的项目）。
- 唯一限制：**LLM 的 API 速率**。
- 这是第 4 天讲的**第三层子智能体协调（舰队）**。
- 回顾三层协调：① 子智能体（父子）；② 交接会话（浓缩目标）；③ 舰队（多实例/多机器）。
- **为什么需要舰队（而非用唯一 session ID 区分多用户查询）？** 同一 harness 实例会共享很多内容（上下文、记忆）；全新项目不该共享记忆，所以用独立实例。两种编排：① 多项目一起跑、汇总结果；② 完全独立跑。

### 2.3 `client.py` —— 命令行接口（CLI）
- 作用：与 harness 交互（类似 Claude Code 的运行方式）。
- 两种模式：
  1. **交互模式（interactive）**：人类用键盘输入。
  2. **无头模式（headless）**：自动化/远程（类似 `claude -p` 命令，完全无界面）。
- **无头模式 vs 自动批准模式**：本地操作多用自动批准；远程虚拟机跑大规模任务用无头模式。两者场景略不同。
- **为什么需要最大工作者（max workers）**？因为消耗 LLM 资源，唯一崩溃原因是限速/请求过多；设上限控制资源消耗。
- **Agentic SDK vs 无头 Claude Code**：
  - 网页应用里要跑智能体环境（不能本地用 Claude Code），两种方法：① 虚拟机无头运行 Claude Code（贵）；② 云提供的 **Agentic SDK**（与 Claude Code 同功能，也贵但表现更好）。
  - 研讨会后可把 Odysseus 转成 SDK，让网页应用访问。

### 2.4 最终形态
- **14 个 Python 文件，约 1000~1200 行**（Claude Code 超 10 万行，我们只 1000 行却运行良好）。

## 三、测试 harness（构建产品验证）

### 3.1 首次测试
- 用 harness 并行构建多个简单产品：**手工咖啡、任务管理工具、清洁器**等（车队运行，每个项目独立文件夹，两阶段：先构建、再同会话二次运行）。
- 关键：此时 **Claude Code 只是被动接口**（发指令），真正执行的是自建 harness。
- 理想下一步：**脱离 Claude Code**，用终端命令直接运行，或加 UI 层（网页输入提示、看思考过程、构建产品）。

### 3.2 案例：用 Odysseus 构建 "Ablation"（AI 研究通讯）
讲者示范"如何正确地用 harness 构建一个产品"。

**① 先想清楚产品与目标（在对 Odysseus 做任何操作之前）**
- 产品：Ablation = AI 研究通讯（深入讨论 AI 研究，非华丽标题）。
- 目标：明确是收入？还是用户参与？
- 重要的事：每篇文章**深入探讨**（无废话、深入的数学 + 可视化解释）；写作风格简单；美学美观简约（参考 **Lenny 通讯**）；订阅人数增长。

**② 把"重要的事"转化为技能文件（这是人类该努力的地方）**
4 个技能文件：
1. **Lenny 设计**：设计系统（用开源模型 GLM5.2 API 浏览 Lenny 网站生成；参考示例技能文件，保证同样详细）。
2. **写作声音（writing voice）**：禁用双破折号、"delve""诚实""真正的游戏改变者"等 AI 腔词，写得像有人关心你。
3. **深度探讨结构（deep-dive structure）**：每期 = 主张 → 为何困难 → 解决过程 → 证据 → 延伸阅读。
4. **编辑（editor）**：读草稿并检查，形成反馈循环。

**③ 给 harness 的提示（分四阶段）**
- 阶段 1：建网站 + 第一期内容。
- 阶段 2：生成 4 篇文章 → **派生 4 个子智能体**各写一篇（每个子智能体 = 一个工具）。
- 阶段 3：整合 4 个智能体的输出。
- 阶段 4：生成一个**验证子智能体**审核所有工作。

**④ 结果**
- 仅靠 4 个技能文件 + Odysseus，产出干净简约、带亮/暗模式、原创图示、无 AI 腔的通讯（约 80~100 次思考-行动-观察循环）。
- 关键：**技能文件只有在控制器决定使用该技能时才完整加载**（渐进式披露）。

## 四、循环工程（Loop Engineering）—— 在 harness 之上加循环

- 循环 = 有时间限制的自动化闭环；循环越多，自动化越强。
- 要把 Ablation 变成"个人公司"（独立运作），需要 3 个循环：

### 4.1 产品循环（Product Loop）
- 流程：用户反馈 → 自动生成 GitHub issue → **Scout**（发现并判断是否修复）→ **Forge**（写修复代码）→ **Mentor**（复现漏洞、挑战修复有效性）→ 创建 PR → 产品自动更新。
- 实现文件：`feedback.py`（找到反馈、避免重复处理、独立工作、生成智能体）。

### 4.2 营销循环（Marketing Loop）
- 流程：网站发布新文章 → **Harold**（读文章写帖子）→ 生成 LinkedIn 帖 + 邮件营销帖 → **Mentor**（审核所有内容）→ 用 **Typefully API** 发布 → 追踪点赞/评论 → 反馈影响后续文章。
- 关键：**自动发帖不够**，还要智能体看反应（多少赞/评论），据此判断"这类帖子受欢迎，下一篇文章可类似"。

### 4.3 销售循环（Sales Loop）
- 流程：**Ranger**（用 **Apollo API** 找潜在客户）→ **Judge**（评分）→ **Lawyer**（写专属冷邮件）。

### 4.4 核心思想：线 vs 圆
- **线性**：决定新内容就结束。
- **循环**：自动闭环 + 反馈机制持续改进。
- 反馈机制随处可见（高效组织都有）；自主系统也必须以循环方式运行。

### 4.5 循环工程作业
- 用自建 harness 建立营销循环：写"内容偏好"技能文件 → 连接 Typefully API（免费计划）→ 设每天早上 8:30 自动发 LinkedIn 帖 → 再加智能体追踪评论/点赞形成闭环。

## 七、其他课堂问答补充

- **能用 Rust 替代 Python 写整个 harness 吗？** 完全可以，没理由只局限 Python，任何语言都行。
- **如何改进 harness？** 从自己的 harness 入手，看它产出的产品种类；为自己制作 harness，编写自己的技能文件（如代码审查技能），让它越来越好。不必依赖服务千万用户、带一堆多余技能的黑箱。
- **斜杠计划（/plan）怎么整合？** 斜杠计划是一种**模式**，本质是**交接（handoff）**的变体。PI 已定义 Planner 子智能体（默认激活就开始规划）；作为用户可用类似 `/handoff` 的扩展实现 `/plan`。
- **知识如何编码进 harness？** 用 **RAG 工具**——工具列表里有一个 rag 工具，遇到大 PDF 需要提取内容时，智能体选择"直接用 rag 工具"。知识与技能都编码在 harness 上。
- **OpenRouter 集成**：给 Gemini 的指令很容易扩展为 OpenRouter（一次会话即可加 `openrouter.py`，模块化简单）。讲者还用 **Fable** 制作了 `ods` 安装时的动画（用 Vizuara 配色）。
- **如何让 harness 自我进化（Vanka 问，整合 Obsidian）？** 可以，但需要设置**监听器（listener）**——决定"什么事件触发自我进化"。
- **CCAF 考试**：非合作伙伴无法注册（只有组织合作或云合作伙伴才能考）；可发邮件升级到 CCAF 课程准备。
- **与 SLM/开源 LM 结合？** 讲者把 Odysseus 连到 OpenRouter（显示 Anthropic Claude Sonnet 5），很多项目通过整合 **GLM5.2** 实现。
- **企业用本地 LLM（Ollama）还是付费服务（Sonnet/Haiku）？**（RetinaVerma 问）讲者认为问题较复杂，建议邮件讨论（他有与行业客户相同的对话）。

## 八、结尾观点与趋势

- **发布自己的 harness**：可放到 GitHub / Hugging Face / LinkedIn 作为个人项目（对比 Hugging Face 的 Tao）。
- **"Harness 即服务（SaaS）"**：未来会有公司把 harness 作为服务卖给企业（企业因安全不愿依赖 Claude Code）。
- **趋势预测**：先转向"闭源模型 + 开源 harness"，再转向"开源模型 + 开源 harness"。
- **为什么没有循环工程库？** 这是简单易得的机会（讲者鼓励建立）。
- 建议：从"线性思维"转向"循环/图思维"。

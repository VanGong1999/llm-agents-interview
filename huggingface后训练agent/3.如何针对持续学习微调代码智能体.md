## 五、Sergio 深入 SFT 与课程设计（10:19–16:47）

### 抽象层级提升
- 在 agent 运行期间，讲**幕后**发生什么。
- 我们**提升了一层抽象**：以前要**生成 Python 代码**、用不同参数**逐个跑训练**；现在**直接给 agent 一个 prompt**，**定义期望的结果**——不同模型/参数组合、用 eval 比较、在数据集上做 **SFT**。
- **人类操作员**只需**观察 agent 的决策**、**验证 artifacts**（不同模型、生成的 **live metrics**）。
- 这就是 Ben 把 prompt 丢进 **Codex** 后，**agent 正在做的事**。

### 系列定位
- 这是**系列第一集**：
  - **第一集：在 agentic traces 上做 SFT**；
  - 后续：**加复杂度**，用 **GRPO**，甚至 **RL environments**；
  - **系列最终目标**：生成一个 **code agent**；本集只做 **SFT on agentic traces**。
- 预期：**不能直接期待一个完整 code agent** 能跑任何任务；而是**一步步走向更大目标**。

### Prompt 即“契约”（contract）
- 与给 Codex 的 prompt 基本相同，设置约束：
  - **SFT train 指定模型**（Gemma 4 的**小版本**）；
  - **指定数据集**；
  - 以前要**为 pipeline 每一步生成 Python 代码**；现在只需给 agent **一组约束**：
    - 在这个模型上训练、用这个数据集、用这个模型版本；
    - **用 HF Jobs 跑**，寻找**最佳参数组合**；
    - **用 Trackio 跟踪每一次 run**，所有 run 必须在**同一个 Trackio project**；
    - **push 每个 adapter** 到 HF repo；
    - **最终权重**是**按 held-out eval 选出的最佳 run**。
- **held-out eval**：把数据集分为**训练集**和**评估集**；训练用训练集，评估集用于**找 agent 能找出的最佳模型**。
- **关键**：不是我们人类在看每个 live metric、选最佳参数；**是 agent 自己在 Trackio live metrics 里选最佳参数**。
- **两个 eval**：在最终权重上跑 **HumanEval** 和 **MBPP**；要求 agent **生成最终分数、加到模型 repo**，并包含**表格**：**job ID、track 链接、最终 repo 链接、每个 eval 指标**。
- 这就是给 agent 的**“契约”**：把高层要求转成 **13 个步骤（a 13 approach）**。

### Agent 需要具备的能力（契约展开）
- **规划**：把高层要求转成步骤；
- **验证文档**：如只给了模型名 **Gemma 4 2B**，要能转成**实际 HF ID**；
- **实现自己的训练脚本**，或配置仓库里已有的；
- **跑 smoke test 和失败分析**：正式 run 前确认——
  - 是否有**权限** push 模型、用 HF Jobs；
  - **格式**是否正确；
  - 训练**是否会 OOM**；
  - 一切确认后再找最佳参数、跑真正训练；
- **记录/跟踪每个 artifact**；
- **基于 eval 集做完整性检查**（前面提到的 eval）；
- **记录每一课/教训（record every single lesson）**。

## 十、Sergio 继续：训练目标与 stack（30:24–39:42）

### 重申训练目标
- 训练**小模型 Gemma 4 2B**；
- **用 agent traces、仅 SFT**；更复杂/高级的 workflow 后续再讲；
- traces 来自**真实 agent sessions**（安全）；
- 模型本来能 follow chat/instructions，现在**学习适应这些 harness**：**如何发起调用、管理多轮设置、生成不同 sub-agent 树**等；
- 目前模型**很小**，只能像普通 chatbot 一样 follow instructions；目标是把它变成**能在 harness 内、给定任务能完成任务**的模型；
- 例：用户说“fix this failing release workflow in this repo”——**当前 Gemma 在 PI harness 里做不到**；用该数据集 + SFT 朝这个方向训练；但**需要更复杂 workflow/训练程序**，后续课程讲；**本阶段只是开始模仿 agentic traces**；
- **不用 rewards、不用 RL environments**；
- **用另一个 agent**（而非自己写代码）：基于 prompt **产出整个训练 pipeline**；我们只需**跟踪 agent 在做预期的事**，最终得到**模仿这些 traces 的模型**。

### 数据安全：清除 secrets
- traces 来自 PI **真实 sessions**，可能含 **secrets/tokens**；推到**公开数据集**前要**去掉/修改**。
- 可用工具 **Piser HF（PII/secrets 清理工具）**（slides 有链接）：把 tokens/secrets 替换掉，使数据可**公开**、**无 secret**。
- 本课用的数据集**已经清理干净**。

### 使用的 stack
- **HF dataset**：存 traces；
- **TRL / PyTorch**：训练不同场景/参数组合；
- **HF Jobs**：**远程运行**，无需本地 GPU；
- **Trackio**：**实时跟踪指标**；
- **HF repos**：存 **model adapters**、**最终模型版本**、**model card**；
- 全部在 **Hugging Face** 内；
- **评估**：几个 benchmark，用 **Inspect AI**，**并行用 HF Jobs + vLLM** 跑；
- 底层：训练脚本用 **Transformers**；**PEFT/QLoRA** 做**参数高效微调**；其余是 HF 生态。
- Agent trace 作为 **bucket** 存在 HF，可查看 **Codex 生成的完整 session**：不同轮次、每个 tool call、检查的不同参数。

### 参数与选择标准
- 希望模型**搜索不同参数**：**learning rate、LoRA rank、sequence length**；
- **sequence length 很重要**：训练**长 traces**（agent traces 是**长文本序列**），**context 和 truncation** 是关键选择；
- 用 **eval loss 作为代理（proxy）**：因为**奖励的是最佳模仿者**；
- **最佳模型 = 最会模仿数据集的模型**，**不是最佳 agent**；本阶段**不评估 agent 能力**；
- 这一规则**直接写进 prompt**。

## 十二、教育性 SFT 讲解（41:14–51:17）

### 推荐学习路径
1. Ben 在 SFT 上发的**很短的文章**；
2. **HF 的 LLM course（hf.co/learn）**——大量 fine-tuning/SFT 细节；
3. **TRL 文档**——更深入。
- 学习轨迹：**短文 → LLM course → TRL docs**。

### 文章定位
- 伴随直播；**每个视频配一篇文章**；不一定是视频 walkthrough，而是**某个主要部分的 bite-size 内容**；本节是 **SFT loop**。
- 可用它**自己搭训练脚本、跳过 agent**。

### 代码层面：SFT 是什么
- 示例**只用 torch + transformers**，**故意不用 TRL**（教育原因）：TRL 抽象掉一些东西；教育上**去掉抽象、用 PyTorch 实现**。
- 但这是**伪代码**：**不能扩展到生产**、**不是你会用于这些模型的代码**；**仅教育**。
- **SFT 是预训练的延续**：都是**预测下一个 token**。预训练：给“the cat sat on the”，模型从词典预测下一个词（“mat”）。
- SFT 的区别：**不用任意字符串**，而用 **traces（现在这么叫）**，即 **instruction–completion pairs / prompt–completion pairs**：输入模型 → 输出。“法国首都是？”→“巴黎”。不是补全字符串，而是**回应字符串**。
- SFT 还教模型**如何使用工具**——对 agents 很重要：展示**如何在 chat template 中组织 tool use**；通过**与预训练类似的 loss** 学习。

### 数据格式：prompt completions + masks
- 数据是 **prompt completions + masks**：一个 user prompt 进、一个 model completion 出。
- 本数据集：**prompts 来自 Mario**，**completions 来自 PI 和 Claude Opus 4.5**。
- **不想让模型学习生成 user 的指令**，而要它**生成 model 的 completions**、**模仿那个模型**——所以**要 mask 掉 user 部分**。
- **这是 SFT 的核心之一**：**mask 数据**，让模型**学 completions 而非 prompt**；这也是与预训练的关键区别。

### Mask 示例
- 词序列：`user: be concise`，completion：`concise`（有点好笑：模型对“be concise”回应“concise”）。
- 用 **mask（labels 格式）**：**-100 记号**表示**忽略**（也可用其他值）；**真实 token IDs** 用于 completion；模型**基于这些 token IDs 学习 completion、更新权重**；**user 侧被 mask、不计 loss**——**SFT 的定义性特征**。

### Transformers 的帮助
- **`apply_chat_template`**：把 trace 以 **Python 格式**应用 chat template；可看到 **user message** 和 **assistant message**（要 agent 学的东西）。
- 给 **tokenizer** 得到 **encoding**——**字符串格式的格式化 trace**，模型可学习。
- 然后：**复制 input_ids**（token ID 格式）；**把非 assistant（非 model、来自 user）的 token mask 成 -100**——**“忽略、不计 loss、只学 model”**。

### 训练循环
- **forward pass** → 生成文本 → **shift & align logits** → **cross-entropy loss** → **更新/优化**；
- PyTorch 典型循环：**Adam 优化器 + cross-entropy loss**。

### 为何仍需理解底层
- 视频大部分让 agent 做、还用 TRL（**高出两个抽象层**）；但**教育上应花点时间看文章**；若难懂，**把 agent 拉进来围绕问题聊**、理解 SFT；
- **这两个方面（data format/masking）是 SFT 的关键**；**agent 不会把知识塞进你脑子**；
- 即便能 prompt 让 agent 做编排任务，**没有扎实理解数据长什么样，可能拿不到结果**。

### 能期待什么结果
- **SFT 是一种模仿/emulation**：教一个模型**模仿 trace 中的内容**（本例是**更好模型的回答**）；
- 大模型比小 Gemma 好——给“好回答”，让它学着这样回答，通过 loss 更新 token；
- **不能期待模型生成比指令更好的内容**；小模型**有能力上限**；
- 但可**聚焦特定领域/用例**：
  - 大 Opus 是**通用模型、多任务很强**；
  - 假设你只有**一个任务**（如**PR triage**：判断 PR 是否与你的兴趣相关）；用**该小用例的 traces**、好例子训练；
  - 模型在**其他领域可能下降**，但**这个小用例提升**，可用于**有限任务集**；
  - 这是 **SFT on traces 可达到的目标**，也是课程可瞄准的终点。

## 十三、Trackio 仪表盘与指标解读（51:17–55:04）

### Trackio 是什么
- 发音随意；**免费**；可**部署在 HF** 分享结果，也可**本地跑**；**无需账号**；**Python 工具 + 小 web app**；
- 创建 **runs**、**projects**，可分组；每个 run 是某个 job 的一次运行，**有颜色编码和引用**；
- **eval 组**和 **train 组**。

### 训练指标（TRL 默认）
- TRL trainer **默认跟踪一组指标**（**semi-opinionated**，SFT 应看的东西，是标准）：
  - **Loss**：在下降——**但降幅不显著**；**平滑可能过多**；**step 数不算高**，可试**更多 step**；loss 下降意味着**生成与应生成的差距缩小**；
  - **Entropy**：总体**下降**——模型预测的**随机性降低**，猜测**不那么随机**，因此**应更准确**；
  - **Token accuracy**：**上升**——若一切正常，应与 entropy 下降**相关**；
  - **Learning rate**：由 trainer 参数和 agent 设定；**应下降**——开始学得多、后期学得少（问题更棘手）；**当前学习率可能不够高**，可探索；
- **held-out 数据集**上算同样指标：**与训练相似**——**好迹象**，说明**没有明显过拟合**；
- 若再看，**会扩大训练、跑更多 step、在不同 learning rate 上多扫几组**。

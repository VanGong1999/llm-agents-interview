# 习题答案

**1.1** (a) 程序：步骤固定，无需判断。(b) 路由器，或带一次分类调用的工作流：路径除分支外固定，标签可抽查。(c) 智能体：路径取决于日志揭示什么，答案可对照日志检查，且调查是只读的。

**1.2** 需要 $(1-q)^{40}\ge 0.8$，其中 $q=(1-r)(1-d)$，故 $q\le 1-0.8^{1/40}\approx 0.00556$。在 $1-r=0.03$ 时，$1-d\le 0.185$，故 $d\gtrsim 0.81$。

**2.1** $T=20$：$20\cdot 8{,}000+1{,}500\cdot 210=475{,}000$。$T=80$：$640{,}000+1{,}500\cdot 3{,}240=5{,}500{,}000$。有缓存时，全价词元为 $c_0+80\Delta=128{,}000$；其余 $5{,}372{,}000$ 按 10% 计费，等价约 $665{,}000$，大约八倍降低（忽略写入缓存的任何溢价）。

**2.2** 朴素循环看不到工具调用，就把截断文本当作答案返回。它应报告不同的状态（已停止），或要求模型在更大输出限制下继续，且绝不把部分文本呈现为完整答案。

**3.1** `Result("budget_exhausted", None, messages, 5)`；`messages` 持有 $1+5\cdot 2=11$ 条。最后一条观测是测试输出，不是对任务的答案；把它当答案呈现会掩盖失败。

**3.2** 令人困惑：参数为 `{"path": 3}` 时，基于路径的门控可能崩溃，或报告「不允许」而非「应为字符串」。不安全：检查 `args["path"]` 的门控可被工具与门控解释不同的参数绕过（额外键、路径列表）。先做验证，使门控看到的正是工具将使用的内容。

**4.1** 例如 `read_file(path, start=1, end=null)` 返回带编号的行，并带页眉「第 $a$–$b$ 行，共 $N$ 行」；超过 300 行的请求返回前 300 行并附通知：「文件有 $N$ 行；请请求更窄范围或使用搜索。」

**4.2** 使用 bash 时，门控看到的是不透明的命令字符串，日志记录自由文本，任何事都可能发生，包括删除数据。使用 `restart_service(name)` 时，门控可对照允许列表检查 `name`，日志结构化，最坏情况只是一次不必要的重启。

**5.1** 十五次各 3{,}000 词元的读取：无省略时约 45{,}000 词元。`keep_last=3` 时：$3\cdot 3{,}000$ 加十二个大约十五词元的占位，约 9{,}200。

**5.2** 保留：任务与完成定义（否则智能体忘记不得编辑测试的约束）；已改文件及原因（否则会重编辑或回退）；当前假设与关键失败行（否则会重新调查）；已失败的方法（否则会重复）；下一步。丢弃：完整文件内容与过时的测试输出——这些可以重新获取。

**6.1** A：$1/61+1/62\approx 0.03252$；C：$1/63+1/61\approx 0.03227$；B：$1/62+1/64\approx 0.03175$；D：$1/64+1/63\approx 0.03150$。顺序为 A、C、B、D。A 虽分别排第一与第二，仍胜过排第一的 C，因为两位排序者都把 A 排得很高。

**6.2** 赞成：它节省后续运行中的再发现。反对：指令来自不可信的仓库内容，可能过时，且 README 已存储它。若写入，记录源路径、提交、日期，以及它源自仓库内容，使后续运行将其当作数据。

**7.1** 编辑或删除失败的测试；对测试输入做特例处理。用评分器中的隐藏测试、检查测试文件未被修改、以及拒绝 `tests/` 下编辑的门控来防止。

**7.2** 重试携带新键，目标端将其视为新请求并发布两次。从操作身份（运行与调用 id，或内容哈希）派生键，在发送前存入挂起记录，重试时复用。

**8.1** $P_{\mathrm{maj}}(5,0.6)\approx 0.683$。相关情形：$0.7\cdot P_{\mathrm{maj}}(5,0.75)+0.3\cdot 0\approx 0.7\cdot 0.896\approx 0.628$，低于独立情形——尽管投票者 70% 的时间独立：一种共享失败模式压过了更高的个体准确率。

**8.2** 例如：「找出 `parse_config` 在何处被调用及其返回值如何使用。将每个调用点报告为 `file:line`，附一句用途说明，再给三句摘要。只读；仅在 `src/` 下搜索；至多 15 步。若一无所获，如实说明。」

**8.3** (a) 工具：有界查找，分诊智能体把结果并入自己的回复。(b) 移交：专家需要整段对话，并将与客户再进行若干轮。(c) 工具：带短报告的查找；分诊智能体决定如何处置。

**9.1** 私有数据：收件箱；不可信内容：来信；对外通信：发送。设计 A：助手只起草，由人发送（去掉自主通信）。设计 B：处理来信时助手没有发送工具，发送发生在另一步，该步只看见用户指令与草稿（把不可信内容与通信分开）。

**9.2** 在门控中，对 `edit_file`：先规范化路径，若以 `.git/` 开头则拒绝，在 `src/` 或 `tests/` 下则允许，否则询问。先规范化，否则 `src/../.git/config` 会通过朴素前缀检查。`Workspace.resolve` 已保证没有任何路径逃出工作区。

**10.1** $\widehat{\mathrm{pass@}3}=1-\binom{2}{3}/\binom{5}{3}=1$，$\widehat{\mathrm{pass}^3}=\binom{3}{3}/\binom{5}{3}=0.1$。对一次提出、一次评判的修复，两者都不合适：报告 pass@$1=c/n=0.6$。若人审查三个候选，才适用 pass@$3$。

**10.2** 差值的标准误约为 $\sqrt{0.72\cdot 0.28/100+0.68\cdot 0.32/100}\approx 0.065$，故两个标准误约 13 个百分点；4 点差距是噪声。在相同任务上配对比较，增加任务，每任务跑若干次试验，并报告区间。

**10.3** (a) 验证器改动：智能体看见的没有不同，故已存轨迹与最终状态仍有效，用新测试重评分；无需重跑。(b) 智能体可见的改动：新指令下智能体行为会不同，故该任务的全部试验必须重跑。(c) 解的改动：oracle 与智能体试验独立，故无需重做任何事；仅重跑 oracle 以确认任务仍然可用。

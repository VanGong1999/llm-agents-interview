def run(task: str, model: Model,
tools: list[Tool], *,
system="You are a careful assistant.",
gate=allow_all, view=lambda m: m,
max_steps=30, log=lambda e: None):
registry = {t.name: t for t in tools}
messages = [{"role": "user", "content": task}]
for step in range(1, max_steps + 1):
# 1. policy: choose the next action
reply = model.next(system, tools,
view(messages))
messages.append({"role": "assistant",
"reply": reply})
log({"step": step, "text": reply.text,
"calls": [(c.name, c.args)
for c in reply.calls]})
# 2. termination
if reply.stop not in ("end_turn",
"tool_use"):
return Result("stopped", reply.text,
messages, step)
if not reply.calls:
return Result("answered", reply.text,
messages, step)
# 3. act and observe
for call in reply.calls:
obs = execute(call, registry, gate)
messages.append({
"role": "tool", "call_id": call.id,
"content": obs.content,
"is_error": obs.is_error})
log({"step": step, "call": call.id,
"error": obs.is_error,
"observation": obs.content[:200]})
return Result("budget_exhausted", None,
messages, max_steps)

3.5 Why a simple loop
The loop descends from ReAct, which
showed that interleaving reasoning with
actions and observations beats either
alone [82]. Two details of that paper
foreshadow the rest of this book. In its
failure analysis, chain-of-thought reason-
ing without actions hallucinated facts
in more than half of its errors, while the
version that could search hallucinated in
none: acting grounds reasoning in obser-
vations. And a small model fine-tuned on
reasoning-and-acting traces (trained fur-
ther on examples of the behavior) beat a
far larger model merely prompted to pro-
duce them. Early frameworks wrapped

3.6 Testing the harness
Because the model is behind an interface,
the harness can be tested with a scripted
model, offline and deterministically. The
companion suite checks, among other
things, that:
• the scripted fix leaves a repository
whose tests pass;
• with an approver that declines every
edit, the edit is refused, the refusal
reaches the model as an observation,
and the repository is unchanged;

• a model that never stops calling

• a truncated generation ends with sta-

• unknown tools, invalid arguments

These tests show the harness behaves
correctly given a sequence of decisions,
not that a model will decide well. Har-
ness bugs are found by unit tests; model
behavior is measured by evaluations.

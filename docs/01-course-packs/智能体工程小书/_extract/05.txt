5.2 Why more context is not
better
Three effects argue against filling the
window.
Attention is finite.
A transformer at-
tends from every token to every other; as
the context grows, each relevant token
competes with more irrelevant ones. Em-
pirically, models retrieve information
placed at the beginning or end of a long
context more reliably than information
in the middle, the lost-in-the-middle ef-
fect [47]. Benchmarks that go beyond
simple “needle in a haystack” retrieval
find that effective context length, the
length up to which performance holds,
is often well below the advertised win-
dow [29]. A study of eighteen models
found performance degrading as input
length grows even on simple tasks, a
phenomenon its authors called context
rot [28]. Details vary by model and im-

does not.
Figure 5.2 shows the original lost-in-the-

and worst in the middle, where accu-

the two curves is evidence in the context

5.4 Layout: stable prefix,
append-only history
Before deciding what to remove, decide
where things go.
• Put stable material first. System
prompt and tool definitions should
be byte-identical across steps, so that
the prompt cache of Chapter 2 hits.
Dynamic content (dates, user names,
retrieved passages) belongs later.
• Append; do not rewrite. Editing an
early message invalidates the cache for
everything after it, and some providers
reject edited histories that contain rea-
soning blocks. If a tool should become
unavailable, it is often better to refuse
calls to it in the gate than to remove
its definition mid-run [48].

• Keep errors visible. A failed action
and its error message teach the model
what not to repeat. Silently removing

def elide_old_results(keep_last=4, min_chars=500):
"""Replace all but the last `keep_last` long
tool results by a stub. The history itself is
untouched; only the model's view shrinks."""
def view(messages: list[dict]) -> list[dict]:
idx = [i for i, m in enumerate(messages)
if m["role"] == "tool"]
old = set(idx[:-keep_last] if keep_last
else idx)
out = []
for i, m in enumerate(messages):
n = len(m.get("content") or "")
if i in old and n > min_chars:
m = {**m, "content":
f"[elided {n} chars; call the "
"tool again if needed]"}
out.append(m)
return out
return view

Near the limit, the model

5.6 Just-in-time context
Up-front loading puts everything possibly
relevant into the context at the start. Just-
in-time loading gives the agent references
and tools to follow them [7]. Coding
agents lean toward the latter: they list
directories, grep and open what matters,
as a programmer would. The cost is ex-
tra steps; the benefit is a focused context

that is never stale.
Most systems are hybrid: a short brief-
ing (what the project is, how to test it,
conventions), often a root file such as
AGENTS.md or CLAUDE.md, is loaded up
front; the rest on demand. Skills apply
the same pattern to procedures.
5.7 Isolation
Finally, a reading-heavy subtask can go
to a subagent with a fresh context: it reads
twenty files, and the parent receives a
paragraph. This is the main reason to use
multiple agents (Chapter 8).

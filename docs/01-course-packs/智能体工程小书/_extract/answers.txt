Answers to exercises
1.1 (a) A program: the steps are fixed and no judg-
ment is needed. (b) A router, or a workflow with
one classification call: the path is fixed except for the
branch, and labels can be spot-checked. (c) An agent:
the path depends on what the logs reveal, the answer
can be checked against them, and investigation is read-
only.
1.2 We need (1−𝑞)40 ≥0.8 with 𝑞= (1−𝑟)(1−𝑑),
so 𝑞≤1 −0.81/40 ≈0.00556. With 1 −𝑟= 0.03,
1 −𝑑≤0.185, so 𝑑≳0.81.
2.1 𝑇= 20: 20⋅8,000+1,500⋅210 = 475,000. 𝑇=
80: 640,000 + 1,500 ⋅3,240 = 5,500,000. With
caching, full-price tokens are 𝑐0 + 80Δ = 128,000;
the remaining 5,372,000 cost 10%, for an equivalent
of about 665,000, roughly an eightfold reduction
(ignoring any premium for writing the cache).
2.2 A naive loop sees no tool calls and returns the
truncated text as the answer. It should report a distinct
status (stopped), or ask the model to continue with
a larger output limit, and never present partial text as
complete.
3.1 Result("budget_exhausted", None, mes-
sages, 5); messages holds 1 + 5 ⋅2 = 11 entries.
The last observation is test output, not an answer to
the task; presenting it as one would hide the failure.

4.1 For example read_file(path, start=1,

string, the log records free text, and anything
is possible, including deleting data. With

5.1 Fifteen reads of 3,000 tokens: about 45,000 tokens

5.2 Keep: the task and definition of done (else the
agent forgets the constraint not to edit tests); files
changed and why (else it re-edits or reverts); the
current hypothesis and key failure lines (else it re-
investigates); approaches that failed (else it repeats
them); next steps. Drop: full file contents and stale test
outputs, which can be re-obtained.

6.2 For: it saves rediscovery in later runs. Against: the

7.1 Editing or deleting the failing test; special-casing
the test’s input. Prevent with hidden tests in the
grader, a check that test files are unmodified, and a

7.2 The retry carries a new key, so the destination
treats it as a new request and publishes twice. Derive
the key from the operation’s identity (run and call id,
or a hash of the content), store it in the pending record
before sending, and reuse it on retry.
